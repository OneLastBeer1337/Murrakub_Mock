Kahn's Topological Acyclicity (G4)

Implemented in prototype/ingestion.py:64-89. Before any solver cycles are spent, validates workflow DAG validity in $O(|V| + |E|)$:

def _validate_acyclic(tasks: list[Task]) -> None:
    in_deg = {t.task_id: 0 for t in tasks}
    for t in tasks:
        for dep in t.dependencies:
            in_deg[t.task_id] += 1
    # Iterative queue processing
    queue = [t for t, d in in_deg.items() if d == 0]
    visited = 0
    while queue:
        curr = queue.pop(0); visited += 1
        for m in dependents[curr]:
            in_deg[m] -= 1
            if in_deg[m] == 0: queue.append(m)
    if visited != len(tasks):
        raise InvalidBatch("Cycle detected in DAG")
Guarantees execution safety prior to optimization

Component 2 Job J2 Gap G10 Principle P3

Feasibility-First Candidate Filtering & Optimistic UCB Exploration

Decouples abstract workflow tasks from hardware configurations. Pre-filters contract-violating profiles ($C(t)$) before optimization (Principle P3), while Upper Confidence Bound exploration (G10) prevents premature profile abandonment.

Principle P3: Feasibility First, Cost Second

Constructs feasible candidate pool $C(t) \subseteq M$ prior to calling the solver (candidate resolution in prototype/registry.py:67-90):

$$C(t) = \left\{ m \in M \;\middle|\; \text{rel}_{\text{eval}}(m) \ge R_{\min}(t) \ \land \ \text{lat}_{\text{eval}}(t, m) \le L_{\max}(t) \right\}$$

  • Guarantees SLA Contract: The solver cannot legally trade SLA breaches for dollar savings.
  • Search Space Pruning: Reduces decision variables from $|T| \times |M|$ to $|T| \times |C(t)|$, accelerating LP solve time by up to an order of magnitude.
  • Fast-Fail Reporting: Infeasible tasks are flagged immediately at admission.

Optimistic UCB Candidate Filtering (G10)

Finding F23 revealed that filtering on raw point estimates permanently blacklisted profiles after a single unlucky execution. Gap G10 enables Beta-Binomial UCB ($z=1.96$) in prototype/profiling.py:162-184 and candidate resolution in prototype/registry.py:67-90:

$$\text{rel}_{\text{UCB}}(m) = \min\left(1.0, \; \hat{p} + 1.96 \sqrt{\frac{\hat{p}(1-\hat{p})}{N_{\text{eff}}}}\right)$$

Cold-start profiles with $N_{\text{obs}} = 0$ default to $\text{rel}_{\text{UCB}} = 1.0$, guaranteeing fair trial before pruning.

Finding F25 Verification: Enabling UCB feasibility recovers a 25% cost penalty by preventing cheap high-performing profiles from being prematurely abandoned on early stochastic noise.

Speaker Notes & Advisor Defense

Defend pre-filtering over multi-objective optimization: Prof. Tossaphol, we specifically evaluated whether reliability should be in the objective function (e.g. min Cost - lambda * Rel). We rejected it: enterprise SLA contracts are step-functions. Delivering 99.5% satisfies the contract; dropping to 94.9% triggers 100% SLA penalties. Pre-filtering guarantees contract compliance.

Explain G10: Without UCB, a profile with 99% true reliability that fails on its first invocation drops to 0.0 point estimate and is permanently banned. UCB provides statistical optimism under uncertainty.

Component 3 Job J3 Formulation Invariants I1–I5

Modular Capacitated Facility Location & The Mandatory Invariant Suite

Formulated as Modular Capacitated Facility Location with knapsack budget constraint (C3). Minimizes fleet provisioning cost while enforcing five non-negotiable invariant assertions across all solver tracks.

Mathematical Program (MCFL-B)

minimize   ∑_{m ∈ M} n[m] · price(m)

subject to:
  (C1) Single Assignment:
       ∑_{m ∈ C(t)} x[t][m] = 1                 ∀ t ∈ T

  (C2) Instance Serving Capacity:
       ∑_{t: m∈C(t)} x[t][m]·load(t) ≤ n[m]·thr(m)   ∀ m ∈ M

  (C3) Fleet Accelerator Budget:
       ∑_{m ∈ M} n[m] · gpu(m) ≤ B

Domains: x[t][m] ∈ {0, 1},   n[m] ∈ ℤ_{≥0}

Proof of Redundancy ($x \le y$): Because $\text{load}(t) > 0$ strictly for all $t$ and $\text{thr}(m) > 0$, $x[t][m]=1 \implies n[m]\cdot\text{thr}(m) \ge \text{load}(t) > 0 \implies n[m] \ge 1$. Explicit linking constraints are mathematically redundant!

Mandatory Invariant Suite (I1–I5)

Asserted in poc/formulation/invariants.py before returning any plan:

InvariantNameFormal Condition & Code Assertion
I1 Assignment $\sum_{m} x[t][m] = 1 \implies \text{set}(x) == \text{set}(T)$
I2 Capacity $\sum x \cdot \text{load} \le n \cdot \text{thr} + 10^{-9}$ (Numerical tolerance)
I3 Budget $\sum n[m] \cdot \text{gpu}(m) \le B$ (Strict hardware cap)
I4 Feasibility $x[t] \in C(t) \quad \forall t \in T$ (SLA compliance; candidate resolution in prototype/registry.py:67-90)
I5 Economy $\forall m \in \text{range}(x): n[m] \ge 1$ (No phantom nodes)

Numerical Tolerance Rationale: Floating-point sum $\sum \text{load}$ can produce $19.999999999999996 \le 20.0$. Tolerance $\text{TOL} = 10^{-9}$ prevents false capacity violations while strictly catching true overages.

Speaker Notes & Mathematical Rigor

Walk through Invariants I1 through I5: Prof. Tossaphol, our formulation guarantees these five invariants on every solver track. If any solver returns an allocation that violates even one invariant, a RuntimeError halts the process.

Address n[m] derivation: If an examiner asks whether n[m] is truly an independent variable: it is an integer decision variable in the MILP solely to linearize step-function capacity. Mathematically, it is derived directly from total routed demand: n[m] = ceil(sum load / thr).

Modeling throughput under Gaussian measurement noise $R$ and process noise $Q$, steady-state Kalman gain converges to constant $K_{\infty} \to \beta = 0.2$. The EMA $\text{thr}_t = (1-\beta)\text{thr}_{t-1} + \beta r$ is mathematically equivalent to the optimal steady-state Bayesian estimator.

Component 9 Job J8 Gaps G6, G7 Interception Gate

Two-Tier Drift Detection: Parameter Cliff Margins & Candidate Caching

Eliminates expensive continuous solver invocations via Tier 1 parameter-margin monitoring ($\Delta R < \epsilon_{\text{rel}}, \Delta L < \epsilon_{\text{lat}}$), triggering re-optimization before catastrophic contract breach.

Tier 1: Parameter Cliff Margins (G7)

Evaluated instantly on incoming telemetry in prototype/profiling.py:376-398 without invoking the combinatorial solver:

$$\Delta R = R_{\text{est}}(m) - R_{\min}(t) < \epsilon_{\text{rel}} \quad (\epsilon_{\text{rel}} = 0.01)$$

$$\Delta L = L_{\max}(t) - L_{\text{est}}(m) < \epsilon_{\text{lat}} \quad (\epsilon_{\text{lat}} = 5.0\text{ ms})$$

  • Zero Solver Overhead: Evaluates in $O(1)$ directly against task SLA floors.
  • Preemptive Interception: Signals drift when a profile approaches the cliff margin, before the SLA is breached.
  • Suppresses noise during initial observations ($N < 5$).

Tier 2 & Candidate Caching (G6)

When margins hold, evaluates decision compatibility across the batch in $O(|T|)$:

$$\text{compatibility} = \frac{1}{|T|} \sum_{t \in T} \mathbf{1}\left[ \text{routing}_{\text{active}}(t) == \text{routing}_{\text{would\_be}}(t) \right]$$

Signals drift when compatibility falls below $\theta = 0.90$.

Candidate Plan Caching (G6): When Tier 2 executes, the computed candidate plan is cached in DriftSignal.candidate. J9 directly consumes the cached candidate, eliminating duplicate solver runs!

Speaker Notes & Computational Efficiency

Explain the resolution of G6 and G7: In v4, drift detection ran the optimizer every few rounds just to see if the plan would change. That doubled solver overhead. Even worse, it was blind to profiles that were degrading right up to the SLA floor.

Show how two-tier solves it: Tier 1 checks parameter margins directly. If a profile's reliability drops within 1% of the task floor, drift fires immediately with zero solver latency. If Tier 2 runs, its candidate is cached so J9 doesn't re-solve.
